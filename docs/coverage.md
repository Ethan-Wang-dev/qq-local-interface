# QQ 本地数据覆盖验证

核验日期：2026-10-23。环境为 Intel macOS 12.7.4、QQ 6.9.85（36362），单个明确授权的本地账号。
本报告仅列统计与能力边界，不包含账号标识、聊天正文或密钥。

## 验收结果

**当前所选数据库及缓存逐项校验通过。按用户要求，频道已排除，收藏全文暂缓；这些范围不计入本轮完整性成功。**

| 项目 | 实机结果 |
| --- | --- |
| 自动发现的数据库 | 21 个：选择 19 个，其中 16 个就绪、3 个未初始化；明确排除 2 个频道库 |
| 原始表 | 192 张全部可读，含 QQ 自定义 FTS5 内容代理 |
| 全量原始行 | 28,397 行，与独立 SQLite 查询逐行多重集合一致 |
| 原始字段 | 600,812 个，逐项核验类型、精确数值或原始字节 SHA-256 |
| 大字段 | 10 个通过字段引用分块完整还原与校验 |
| 原始表导出 | 192 张表全部完整导出，自包含 JSONL 与原始表再次逐项比对 |

同一条消息可包含多个元素，因此元素数与消息数不同。12 种元素全部可分类并读取原始字段。
文本以外的消息仍保留 `quality.status:metadata_only`，不把字段可读等同于业务内容已完整理解。

这个结果不代表未来版本或未出现的消息类型都已完成语义解析。未知元素仍能通过原始消息体读取，禁止静默丢弃。

## 这轮修复

- 依照原生元素类型分类，修复文件预览/视频误判图片、QQ 表情误判视频等问题。
- 群名改读真正的群名字段，避免把群主 UID 当作群名。
- 全部辅助库自动发现，补齐收藏、表情、公告、资源、设置和频道消息表的通用访问入口。
- 提供精确 SQLite 字段编码、长字段分块、无 rowid 表定位与完整表导出。
- 为联系人、会话和群成员补齐后续分页，避免把首批结果当作全量。
- 图片、音频、视频及其他缓存均生成不可变副本，原缓存后续变化不影响旧快照读取。
- 变更流增加数据库、群成员关联和媒体事件。
- 缺 key 的辅助库有明确不可用状态；严格模式保持上一代，显式部分同步保留可访问数据并报告缺口。
- 频道数据库可显式排除并在 coverage 中保留范围，避免未使用的频道库阻塞日常严格同步。
- 本地收藏分开返回摘要和详情缓存状态；专用全文导出会拒绝缺正文的结果。该能力的云端扩展已暂缓。

## 尚未通过的范围

- 频道按用户要求排除（guild1.db、guild_msg.db）。guild1.db 的密钥和内容仍未验证，不以排除代替成功，也不推断它为空。
- `collection.db` 已解密。打开收藏列表后读取到 **7 条真实摘要**；此前的空快照只是未加载。打开详情后本机正文表仍为 0 行，全文需要独立的授权会话，已按用户要求暂缓，详见 [收藏调查](favorites.md)。
- 3 个仅有扩展头的库尚无 SQLite 数据页，不能算作相应业务类型内容已验证。
- 本地没有保存的历史、远程附件、合并转发内层数据及已删除数据，不会由通用接口凭空补齐。
- 对于被选中的非私聊/群聊消息表，可用 datasets/records 访问；无实际消息样本的表不计入规范化消息语义覆盖。
- 原生字段全部可读，不代表每个 QQ 内部字段都已有业务含义解释。

## 如何复测

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m compileall -q src tests tools
.venv/bin/python tools/audit_coverage.py --export-tables
.venv/bin/python tools/audit_transports.py --core-only
```

`audit_coverage.py` 独立读取 SQLite 原始值，再与接口逐字段比较；不调用生产代码的字段摘要函数来构造预期值。
它覆盖全部表和全部行，不使用仅抽样的健康检查。导出再次从 JSONL 还原精确字段并与原始表比较。
媒体校验读取每个独立快照文件的全部字节，并逐块与 API 返回值核验。

详细报告写入私有 vault 的 `coverage-report.json` 与 `transport-report.json`，真实导出也只写入私有 vault。
`accessible_data_passed:true` 表示就绪数据全部比对通过；`all_requested_databases_accessible:true`
表示所选本地库无解密缺口。`all_local_databases_accessible:false` 保留未验证的排除范围，不能据此宣称全部 QQ 数据完整。
复测时 QQ 本地数据可能变化，数量和快照 ID 应以新生成的报告为准。
